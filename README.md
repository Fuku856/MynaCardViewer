# マイナカード券面ビューア

マイナンバーカードの券面確認APから、顔写真・氏名・住所（券面の画像）・生年月日・性別を読み取って表示する Windows アプリです。
PC/SC 対応の NFC リーダー（Sony RC-S370 など）で動きます。読み取った情報は保存しません。

## 使い方
1. `dist\MynaCardViewer.exe` を起動する
2. 確認モードを選び、カードをリーダーに置いて「次へ」を押す
3. 照合番号Bを入力して「読み取る」を押す
   - 生年月日：券面の**和暦**の年2桁＋月2桁＋日2桁（例：昭和60年4月12日 → 600412、元年は 01）
   - 有効期限：券面の有効期限の**西暦**年4桁（例：2034年4月12日まで有効 → 2034）
   - セキュリティコード：券面の4桁

## 確認モード
| モード | 表示する内容 |
|---|---|
| 20歳以上・未満の確認 | 「20歳以上」「20歳未満」を大きく表示＋顔写真・氏名 |
| 年齢の確認 | 「56歳」のように満年齢を大きく表示＋顔写真・氏名 |
| 選択した情報を表示 | 顔写真・氏名・住所・生年月日・性別から、読み取り前に選んだものだけ |

生年月日の月日が券面で不明な場合、年齢は「19〜20歳」のように幅で表示し、20歳の判定がつかないときは「判定できません」と表示します。

## 読み取り履歴
開始画面の「読み取り履歴」から見られます。読み取りに成功したときだけ、次の項目を `%LOCALAPPDATA%\MynaCardViewer\history.dat` に**暗号化して**保存します。
- 取得日時（秒まで）、取得モード、取得した情報の種類
- 氏名の冒頭一字（氏名を表示したときだけ）
- 住所の都道府県（住所を表示したときだけ）
- 生年月日の日（生年月日を表示したときだけ）

券面確認APの氏名・住所は画像なので、冒頭一字と都道府県は、アプリに同梱したオープンソースの OCR エンジン Tesseract で読み取っています（結果画面を表示した後に裏で処理します）。冒頭一字は前処理を変えた複数の読み取り結果の多数決、都道府県は 47 都道府県のどれかに一致した結果だけを採用します。読めなかった場合は「（判読不可）」と記録します。形の似た字や異体字（例：髙→高）は誤読することがあります。
履歴画面で、選んだ行やすべての履歴を削除できます。

## セキュリティ
- **履歴の暗号化**: Windows DPAPI（今の Windows ユーザーに紐づく鍵）で暗号化します。同じ PC の別ユーザーや、ファイルを持ち出した人は読めません。改ざんされたファイルは読み込み時に検出し、勝手に上書きしません。旧版の平文 `history.csv` は、起動時に暗号化ファイルへ移したうえで、0 で上書きしてから削除します。
- **保存しないもの**: 照合番号B、顔写真、氏名・住所の画像、生年月日・性別の全体は保存しません（メモリ上だけで扱い、「最初に戻る」や中断で画面から消します）。
- **カードからのデータは信頼しない**: 偽造カードやスマホのカードエミュレーションを想定し、券面データの長さに上限を設け、壊れたデータは読み取りエラーにします。画像は想定した形式（顔写真 JPEG2000、氏名・住所 PNG）だけで開き、巨大画像は拒否します。
- **DLL 乗っ取り対策**: winscard.dll / crypt32.dll は System32 から絶対パスで読み込みます。
- **照合番号の入力欄**: 伏せ字表示が既定で、選択しただけではクリップボードに渡りません。
- **OCR**: OS やクラウドの OCR は使わず、同梱した Tesseract 5.5.3（Apache-2.0、conda-forge のビルド。取得するパッケージは `tools/tesseract-win-64.lock` の SHA-256 で固定）を PC 内で動かします。画像はファイルに書かず標準入力で渡し、渡すのはアプリが作り直した PNG だけです（Tesseract は画像でない入力をファイル名・URL の一覧として扱うため）。環境変数はプロキシ設定なども引き継ぎません。Tesseract は URL 入力のための通信ライブラリ（libcurl）をリンクしていますが、URL を渡さないので使われません（認識中にプロセスが通信口を開かないことを確認済み）。読めなかったときだけ、個人情報を含まない診断ログ `ocr_diag.log`（画像形式と認識文字数のみ）を残します。

## 真正性の確認（偽造・複製カードの検出）
読み取るたびに次の3段階を確認し、すべて通ったときだけ結果画面に緑の「✔ 真正性を確認しました」を出します。
1. **発行者証明書**: カードの EF 0004 の証明書が、アプリに組み込んだ J-LIS の CA 公開鍵（証明者鍵ID 5000023）で署名されていること
2. **券面データの署名**: 顔写真・氏名・住所・生年月日・性別・カード公開鍵が、1 の証明書の鍵で署名されたとおりであること（1 バイトでも書き換えると失敗）
3. **カードの実在**: アプリが毎回作る乱数に、カードの秘密鍵で署名させ、2 で確かめた公開鍵で検証できること（データだけ複製した偽カードは失敗）

どれかに失敗すると赤い「✖ 真正性を確認できません」を出し、20歳確認・年齢確認の大きな判定は「判定できません」にします（カードの記載内容は参考として小さく表示）。履歴にも「真正性」の列で記録します。
有効期限（DF29）は券面データの署名の対象外なので、判定には使っていません。

方式と CA 公開鍵は [soltia48/myna-card](https://github.com/soltia48/myna-card)（MIT License）を参考にしました（[THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)）。

### 残るリスク（利用上の注意）
- **失効は確認していません**: 紛失・廃止の届けが出たカードかどうかはオンラインの照会が必要なため、確認していません。本物のカードを他人が使う場合も、真正性の確認は通ります。**顔写真と本人を必ず見比べてください。**
- **CA 鍵の更新**: J-LIS が券面確認AP の CA 鍵を新しくした場合、新しいカードは「確認できません」になります。その場合はアプリの更新が必要です。
- **同じ Windows ユーザーで動くマルウェアからは守れません**: DPAPI はログイン中のユーザー本人の権限で復号できるためです。
- **exe にはコード署名がありません**: 配布する場合は、改ざん検知と SmartScreen 対策のためにコード署名をおすすめします。

照合番号Bを間違えると残り回数が1回減ります。0回になるとロックされ、市区町村の窓口で解除が必要です。

## 接続が切れたときの自動中断
入力中・読み取り中に次のことが起きると、入力内容を消して開始画面に戻ります。
- カードがリーダーから離れた（離してすぐ置き直した場合も含む）
- カードリーダーが外れた
- カードとの通信でエラーが起きた

結果画面を表示したあとにカードを離しても、結果画面はそのまま残ります。

## ビルド
`build.bat` を実行すると、仮想環境の作成、Tesseract の取得（初回のみ。`tools/fetch_tesseract.ps1`）、テスト、exe のビルドまで行います。

## リリース
GitHub の Releases から手動でリリースを作成（公開）すると、GitHub Actions がテストと exe のビルドを行い、
`MynaCardViewer-<タグ>.exe` と SHA-256 のファイルをリリースに添付します（`.github/workflows/release.yml`）。

| 対象ブランチ | リリースの種類 |
|---|---|
| `main` | 正式リリース |
| `dev` | プレリリース（作成時にチェックし忘れても、ワークフローがプレリリースに変更します） |
